# Экранное время (Creker Screen Time)

Android-приложение для личного учёта экранного времени. Читает статистику
использования локально, через системный API `UsageStatsManager`, хранит её в
локальной базе Room и показывает, сколько времени вы провели в каждом приложении
за выбранный период. Никакого сервера, никакой сети — данные не покидают устройство.

## Что умеет

* **Учёт по каждому приложению** — время с точностью до секунды.
* **Периоды**: сегодня, неделя (7 дней), месяц (30 дней) и произвольный период
  с выбором дат «от» и «до».
* **Общая статистика** — суммарное экранное время за период крупно вверху экрана,
  ниже список приложений, отсортированный от самого используемого к наименее
  используемому, с полоской-долей и количеством запусков.
* **Формат времени** — часы : минуты : секунды, например `2ч 15мин 40сек`.
  Ведущие нулевые единицы опускаются: `15мин 40сек`, `40сек`.
* **Иконки и названия приложений** берутся из `PackageManager`.

## Как считается время

`UsageStatsManager.queryUsageStats()` возвращает готовые суммы, но они привязаны
к системным «корзинам» и на произвольном интервале дают неточный результат.
Поэтому приложение работает с сырым потоком событий `queryEvents()` и само
собирает сессии:

1. `ACTIVITY_RESUMED` (`MOVE_TO_FOREGROUND`) открывает сессию приложения.
2. Сессию закрывает `ACTIVITY_PAUSED`, выход другого приложения на передний план,
   выключение экрана (`SCREEN_NON_INTERACTIVE` / `KEYGUARD_SHOWN`) или выключение
   устройства. Учитывать выключение экрана обязательно: часть прошивок не шлёт
   `PAUSED`, и телефон, забытый на столе, «накрутил» бы часы использования.
3. Незакрытая сессия обрезается текущим моментом, а не концом запрошенного окна.
4. Сессии, пересекающие полночь, режутся по локальной полуночи и попадают в оба дня.

Логика вынесена в `core/` и не зависит от Android — она покрыта unit-тестами
(`app/src/test/.../core`).

## Почему нужна локальная база

Система хранит подробные события всего несколько дней. Чтобы недельный и
месячный срезы вообще имели смысл, приложение переносит прочитанное в Room:

* пересчитываются только те дни, которые ещё можно восстановить из событий
  (последние 7 суток), более старые записи остаются нетронутыми;
* пересчёт целыми днями делает повторную синхронизацию идемпотентной;
* `UsageSyncWorker` (WorkManager) синхронизирует данные раз в 6 часов, чтобы
  история накапливалась, даже если приложение долго не открывали;
* если система вернула пустой поток событий (например, доступ отозвали),
  сохранённые дни не затираются.

Пока истории меньше, чем охватывает выбранный период, на экране показывается
пояснение, с какой даты данные реально есть.

## Разрешение

«Доступ к данным об использовании» (`PACKAGE_USAGE_STATS`) — специальное
разрешение: его нельзя запросить диалогом, пользователь включает его на системном
экране настроек. При первом запуске приложение показывает экран с объяснением и
кнопкой, ведущей туда; статус перепроверяется при каждом возврате в приложение.

`QUERY_ALL_PACKAGES` нужен, чтобы на Android 11+ получать названия и иконки
приложений, о которых сообщил `UsageStatsManager`.

## Стек

Kotlin, Jetpack Compose (Material 3), Room, WorkManager, Coroutines/Flow.
`minSdk 26`, `compileSdk`/`targetSdk 35`. Зависимости внедряются вручную через
`AppContainer` — граф слишком мал, чтобы тянуть DI-библиотеку.

```
app/src/main/java/com/creker/screentime/
├── core/          # чистый Kotlin: сессии, периоды, форматирование времени
├── data/
│   ├── local/     # Room: сущности, DAO, база
│   ├── system/    # UsageStatsManager, PackageManager, проверка разрешения
│   └── UsageRepository.kt
├── work/          # фоновая синхронизация
└── ui/            # Compose: экран статистики, экран разрешения
```

## Сборка

```bash
./gradlew assembleDebug          # APK
./gradlew testDebugUnitTest      # unit-тесты
```

Нужны JDK 17 и Android SDK (API 35).

## Чего пока нет

Намеренно вне текущего объёма: интеграции с внешними сервисами (Notion,
TickTick), лимиты на использование и уведомления. Всё это добавляется поверх
существующей модели данных отдельным шагом.
